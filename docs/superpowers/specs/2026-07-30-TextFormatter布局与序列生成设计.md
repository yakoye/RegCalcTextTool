# TextFormatter 布局与序列生成设计

## 目标

重新安排 TextFormatter 的操作区域，使功能分类和参数始终位于原文、结果文本框之前；强化分类项的下拉视觉；重新设计序列生成布局，并支持十六进制序列输出。

## 页面顺序

TextFormatter 主面板按以下顺序排列：

1. 页面标题与“保存原文与结果”。
2. 功能分类栏。
3. 当前选中功能的参数区。
4. 状态提示与“清空全部”。
5. 原文、传递按钮和结果文本框。

分类列表和具体功能列表继续限制最大高度并使用内部滚动，不能依靠页面无限向下展开。

## 功能分类视觉

每个分类标题使用完整的浅色下拉控件样式：

- 白色半透明背景、清晰边框和圆角。
- 标题、功能数量和右侧箭头保持同一行。
- 默认显示向下箭头，展开后箭头旋转。
- 展开状态使用浅绿色背景和绿色边框。
- 具体功能列表在分类内部滚动，不覆盖参数和文本框。

## 序列生成

### 第一组

第一组依次显示：

1. 开始
2. 结束
3. 位数
4. 数量
5. 进制
6. 顺序
7. 分隔方式
8. 自定义分隔符，仅在分隔方式为“自定义”时出现

桌面端按单行紧凑排列。位数只需容纳两位数；数量可容纳 `100000000`；进制、顺序和分隔方式使用紧凑下拉框。手机端使用两列，宽度不足 360px 时改成单列。

### 第二组

第二组只显示：

- 生成到结果
- 生成到原文

### 进制规则

- 默认使用十进制，保持现有输出兼容。
- 十六进制输出使用大写数字和 `0x` 前缀。
- 位数只计算数字部分，不计算符号和 `0x`。
- 示例：数值 `10`、位数 `4` 输出 `0x000A`。
- 负数示例：数值 `-10`、位数 `4` 输出 `-0x000A`。
- 开始和结束仍按十进制整数输入。
- 实际生成范围和数量上限仍为 10000，避免页面卡顿。

## 偏好保存

在现有 TextFormatter 设置中增加 `sequence.radix`：

- 合法值为 `10` 或 `16`。
- 老版本没有该字段时使用 `10`。
- 修改序列设置并生成后保存该偏好。
- 不改变原文、结果和敏感 Base64 的存储策略。

## 测试

- 单元测试覆盖默认十进制、十六进制补零、负数、非法进制和随机/排序后的十六进制输出。
- UI 测试覆盖页面 DOM 顺序、明显的下拉箭头、自定义分隔符条件显示和新进制字段。
- 浏览器回归覆盖桌面和手机尺寸、菜单内部滚动、序列生成到结果及自定义分隔符切换。
